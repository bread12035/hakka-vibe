# 任務素材採用生成，而非現成的開源專案

Fixture 是一個生成的 Python repo，bug 由 mutation script 機械注入（隨機選定模組的一行做標準變異），整包 vendor 進 `fixtures/` 凍結。採用生成而非現成專案，是因為素材難度必須是可調的旋鈕：所有 experiment 都仰賴八輪以上的 context 累積才有訊號，訊號不足時要能加深模組層數重新生成。

## Considered Options

- **Vendor 現成的開源專案**：耦合關係是自然長出來的，比合成的更真實。否決原因是難度不可調，訊號不足時只能重新尋找專案；且上游若刪除或改名，實驗無法重現。
- **由人手工設計 bug 的藏匿位置**：否決。設計者知道答案，會無意識地讓根因過於好找。機械注入讓「藏得巧不巧」成為隨機變數。

## Consequences

- **所有數字僅在 arm 之間相對可信，絕對值不可外推到真實專案。** 合成程式碼結構工整、無死碼、無誤導性註解，缺少真實 repo 中最耗 token 的意外複雜度。
- 生成素材與解題模型同屬 Claude 家族，存在效度威脅。機械注入 bug 降低但未消除這個風險。
- 因此設下 **calibration gate**：baseline 執行少於八輪的素材視為不合格，須加深後重新生成。難度從假設變成驗收條件。
- 六個 experiment 完成後，可挑效果最大的一個補跑真實專案作為驗證。
